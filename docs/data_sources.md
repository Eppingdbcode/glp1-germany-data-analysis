## How to interpret the provenance layer

### Archived project input versus current official source

For redistributable inputs, the **exact project input** link opens the archived file actually used in this analysis. That repository archive is the reproducible snapshot even if an official dataset later changes. The **official source** link identifies the table, publication or portal maintained by the responsible institution and establishes provenance. A GENESIS official-source link opens the table interface and may require the user to select parameters and export data; it is not represented as a guaranteed direct download of the identical archived ZIP. Reviewers should use both links for their distinct purposes.

### Automated processing versus manual structuring

The analytical notebooks reproducibly consume the published processed CSVs, validate assumptions and create figures or Power BI exports. They do not currently provide complete RAW-to-processed builders for the Destatis ZIP files. RKI aggregate estimates and confidence intervals were manually transcribed from the publication; no OCR or individual-level data were used. EMA fields were manually curated from the listed EPAR pages. No acquisition API is implemented or claimed.

### Conditional WIdO reproduction

WIdO row-level data are not redistributed because reuse rights were not confirmed. A reviewer with legitimate access can follow the export instructions in [`data/README.md`](../data/README.md), place the file at `data/external/wirkst_export.csv`, and run notebook 05. Without that independently obtained file, the public clone preserves provenance, schema, code, aggregate displayed results and limitations, but cannot reproduce the WIdO module from source observations.

### Current RAW-to-processed automation limitations

The repository preserves public RAW snapshots and processed analytical snapshots, but preservation is not equivalent to an automated acquisition pipeline. Notebook 01 inventories files, inspects Destatis archive contents and previews processed tables; it does not reconstruct every processed table from RAW. Closing this gap would require separately approved, source-specific transformation code and validation fixtures. Official APIs may be evaluated as a future route, but they were not the historical acquisition method used here.
